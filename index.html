Abstract

Language-model agents increasingly rely on harnesses that manage bounded context, persistent memory, tools, verification, and repeated execution, but existing notions of model capability do not quantify the computational resources these mechanisms consume. We develop a theory of these costs through the Language Model Agent Machine (LAM), a resource-bounded model that fixes the underlying semantic model while explicitly charging harness-level resources. Our theory yields four classes of results. Communication: LAM execution and red–blue pebbling are instancewise equivalent at the level of simultaneous call–transfer budgets, yielding the full discrete resource frontier and transferring classical I/O lower bounds to context–memory traffic. Access: memory interface changes asymptotic cost, including a Θ(n)\Theta(n)Θ(n) separation between random and non-speculative sequential access on pointer chasing and an exact single-stack FIFO frontier. Recomputation: bit-reversal DAGs require Θ(n2/(C+S)+n)\Theta(n^2/(C+S)+n)Θ(n2/(C+S)+n) model calls with context capacity CCC and persistent-memory capacity SSS, quantifying when stored intermediate state avoids repeated semantic computation. Reliability: we derive tight stage-local sampling bounds, exact imperfect-verification costs, and a Young–Daly-type checkpoint law with a closed-form optimal verification interval. Controlled experiments and held-out evaluations on GPT-6 Astra compare development-derived communication and reliability predictions with measurements, including checkpoint optima and a held-out policy-selection tournament conditional on a programmatic segment check; held-out chained MATH additionally exposes an observed tradeoff between whole-task call granularity, logical input traffic, and reliability. Prescribed-schedule runs are reported separately as implementation checks. Together, these results provide a resource theory for the computational cost of language-model agent harnesses. Project page: https://anonymous1776research.github.io/LAM-ICLR2027/.

The Language Model Agent Machine

Modern language-model agents are computational systems built around a model, not isolated model calls: a harness manages context, persistent state, tools, verification, and repeated execution. Existing theory largely characterizes what models or agentic extensions can compute; what it does not characterize is the resource cost of realizing that computation through a harness. Two agents using the same underlying model can have the same semantic capability yet require asymptotically different numbers of model calls, context–memory transfers, memory operations, or verification steps. Universality is in fact cheap in our model, costing O(1)O(1)O(1) model calls and block movements per simulated Turing-machine step at a constant number of context blocks (Proposition 8, appendix). This paper therefore asks a different question: holding semantic capability fixed, what resources must a harness spend to execute a computation, and what is the optimal tradeoff among model calls, context, persistent storage, communication, and verification?

Machine model. The LAM models harness-level execution, the prompt construction, state, memory, tools and verification around a model, not the model’s internal computation. Fix an input size nnn and a finite alphabet Σ\SigmaΣ; a semantic block is a fixed-width unit of task-relevant information, an element of Bn=Σb(n)\mathcal{B}_n=\Sigma^{b(n)}Bn​=Σb(n). A LAM is a tuple

Λ=(L, ctrl, X, M, Otool, Over),\Lambda=(L,\ \mathrm{ctrl},\ X,\ M,\ O_{\mathrm{tool}},\ O_{\mathrm{ver}}),Λ=(L, ctrl, X, M, Otool​, Over​),

where LLL is the model interface, ctrl\mathrm{ctrl}ctrl the harness controller, XXX the active context (at most CCC blocks available to the next model call), MMM the persistent memory (at most SSS blocks across calls, outside XXX; a stored block must be retrieved into XXX before a call can use it, the persistent copy staying in place), and OtoolO_{\mathrm{tool}}Otool​ and OverO_{\mathrm{ver}}Over​ the tool and verifier interfaces. A call to LLL consumes blocks in XXX and inserts its output as a new block of XXX, so a call takes at most C−1C-1C−1 argument blocks. A tool returns a semantic block through an explicitly charged operation; a verifier returns a tag only (accept/reject), inserts no block, and may inspect all CCC resident blocks. Each interface is a fixed map of its opcode and argument blocks alone: no interface sees the input, MMM, or a block not passed to it. The controller is a finite control with tag and address registers that see block contents only through returned tags and decoded addresses, plus the occupancy pattern of XXX and public step counters.

Value provenance (Definition 1). To separate harness orchestration from semantic computation, every semantic block must originate from an input, a declared constant, or a charged model or tool call. Copying, movement, and storage preserve this origin, while recomputation creates a new occurrence of the same computational value. The controller may route, copy, store, retrieve, and schedule existing blocks, but it cannot create semantic blocks otherwise. This restriction is load-bearing: it lets differences in execution cost be attributed to harness design rather than to a stronger underlying model.

Two classical theories anticipate two of these resources: the red–blue pebble game of Hong and Kung lower-bounds the traffic between a small fast memory and a large slow one, and reliable computation from unreliable components anticipates an agent whose transitions are expensive and imperfect. An agent exhibits both at once, and the LAM recovers and sharpens both classical theories: Theorem 1 transfers every Hong–Kung I/O lower bound instancewise to context–memory traffic, and Theorem 6 recovers the Young–Daly checkpoint law with its exact cost, a closed-form optimum and the class of rollback policies in which it holds.

What the LAM abstraction adds. The resource laws do not follow from their classical counterparts by renaming memory or checkpoint variables. Each requires an execution-level bridge between a harness trace and the corresponding mathematical object.

Results

The results isolate four harness costs: communication, access, recomputation and reliability. Each result states a design Problem, its Assumptions and its Conclusion. Comparisons hold the semantic oracle fixed; only the harness changes.

Numbering follows the submitted manuscript. Theorems 1 to 6 appear in the main text; the other results appear in the appendices.

Common definitions

Value provenance (Definition 1). Every semantic block originates from an input, a declared constant, or a charged model or tool call. The controller may route, copy, store, retrieve and schedule blocks, but never manufacture one. Under this axiom, the lower bounds concern the harness rather than the model.

Vertex-granular GGG-evaluation (Definition 2). A vertex-granular evaluation of an LLL-realisable DAG GGG is a provenance-respecting LAM execution that produces the designated sinks of GGG, where each charged semantic call implements at most one declared vertex operation of GGG. The execution may copy, move, store, retrieve, evict and recompute values arbitrarily. Two conventions fix how sources enter:

  • Memory-initialized: all source blocks are initially stored in MMM, the context XXX starts empty, and every designated sink is resident in XXX or MMM at termination.
  • Input-delivered: each source is instead delivered exactly once through the input port.

Communication: replay or persist?

Theorem 1 (red–blue pebbling correspondence).

For memory-initialized vertex-granular evaluations, classical I/O bounds become context–memory traffic bounds, and the two models share the whole feasible resource region.

Problem. How much context–memory traffic is required to evaluate a fixed computation DAG?

Assumptions.

  • GGG is an LLL-realisable computation DAG with designated sinks. Consider memory-initialized vertex-granular GGG-evaluations with capacities (C,S)(C,S)(C,S); recomputation is allowed.
  • Value provenance holds, and all semantic working storage is counted inside CCC.
  • A vertex of in-degree ddd requires C≥d+1C\ge d+1C≥d+1, so that its arguments and result co-reside.

Conclusion. The correspondence works in both directions:

  • Every memory-initialized vertex-granular GGG-evaluation with capacities (C,S)(C,S)(C,S) induces a legal red–blue pebbling with at most CCC red and SSS blue pebbles, exactly one Compute move per model call, and at most one Load or Store move per context–memory transfer.
  • Conversely, every such pebbling induces a vertex-granular evaluation on a random-access LAM with no larger call or transfer budget.

Hence the two models have the same feasible call–transfer budget pairs and the same discrete Pareto frontier. In particular,

min⁡Qblk=IOC,S(G),\min Q_{\mathrm{blk}}=\mathrm{IO}_{C,S}(G),minQblk​=IOC,S​(G),

where IOC,S(G)\mathrm{IO}_{C,S}(G)IOC,S​(G) is the minimum pebbling load-and-store count, attained by a random-access machine. Every red–blue I/O lower bound therefore lower-bounds context–memory traffic.

The correspondence is instancewise. It preserves every priced optimum

min⁡{λNN+λQQblk}\min\{\lambda_N N+\lambda_Q Q_{\mathrm{blk}}\}min{λN​N+λQ​Qblk​}

for all λN,λQ≥0\lambda_N,\lambda_Q\ge0λN​,λQ​≥0 (Corollary 9). It also preserves feasibility under every simultaneous call and transfer budget, hence the entire discrete Pareto frontier of (N,Qblk)(N,Q_{\mathrm{blk}})(N,Qblk​) (Corollary 10).

The evaluation-to-pebbling direction applies to every memory interface, counting pushes, pops, reads and writes as loads and stores.

Recomputation: persist or regenerate?

Design rules

  • Send a step its dependencies, not the history. On chains whose steps read O(1)O(1)O(1) earlier blocks, dependency-only prompting uses linear rather than quadratic input traffic (Proposition 12). The measured frontier-model factors are 7.1×7.1\times7.1× on the synthetic chain, 11×11\times11× on development MATH and 10.9×10.9\times10.9× on held-out MATH.
  • Reach state by random access. Pointer chasing has a Θ(n)\Theta(n)Θ(n) memory-operation gap over non-speculative sequential access (Theorem 2). The broader read-only result gives an Ω(n)\Omega(n)Ω(n) lower bound on total sequential head movement even with speculation (Proposition 14).
  • Persist reusable blocks. Bit-reversal reuse gives a Θ(n/C)\Theta(n/C)Θ(n/C) model-call gap in the stated sublinear-context regime (Theorem 3); linear call complexity holds exactly when total semantic capacity C+SC+SC+S is linear in nnn.
  • Buy feedback, then choose the checkpoint interval. On the stage-local hard family, feedback removes the log⁡(n/δ)\log(n/\delta)log(n/δ) sampling factor (Theorems 4 and 22). With an imperfect verifier, repeated checks improve accepted-error odds only for 0<pa<1−pr0< p_a<1-p_r0<pa​<1−pr​; if pa=0p_a=0pa​=0, one check suffices (Theorem 5). Experiments

Although the primary contribution is theoretical, experiments play two roles. All model-based experiments use the same fixed GPT-6 Astra deployment. Held-out tests compare development-derived quantitative predictions or policy choices with disjoint evaluation data, covering communication, checkpointing and reliability. Implementation checks verify that prescribed schedules realize their analytically determined resource accounting; these are reported separately and are not treated as empirical tests of lower bounds. Development or calibration data and held-out evaluation data are disjoint; forecast parameters and policy-selection rules determined from the former remain fixed on the latter. Success rates use Wilson 95% intervals, token means use chain-level bootstrap intervals, and paired comparisons use exact McNemar tests.

Execution granularity is itself a resource choice. The choice of semantic-call granularity therefore determines which communication–reliability tradeoffs are available to the harness, and the vertex-granular theory characterizes the resource frontier of stepwise execution rather than of unrestricted whole-task calls.

The bit-reversal DAG Δnrev\Delta^{\mathrm{rev}}_nΔnrev​ is instantiated with fixed semantic vertex operations; each model call receives only the blocks required by its scheduled vertex, and the controller enforces the prescribed context and persistent-memory capacities. Conclusion

LAM makes agent-harness architecture a mathematical object whose resource requirements can be bounded, compared, and optimized while semantic capability is held fixed. Across communication, memory access, recomputation, and reliability, the framework yields exact feasible regions, lower bounds, and closed-form resource tradeoffs. The experiments compare frozen predictions with measurements while also exposing the scope of the theory: dependency-aware routing sharply reduces logical input traffic within stepwise execution, whereas held-out chained MATH shows that a whole-task call can use still less input traffic at lower observed reliability, outside the vertex-granular frontier. Together, these results separate semantic capability from the resource cost of realizing that capability through an agent harness. LAM therefore provides a resource theory of agent execution: harness architecture determines which call, memory, communication, and reliability tradeoffs are achievable even when the underlying semantic model is held fixed.
