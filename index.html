Abstract

A deployed language model is one component of a persistent system: a bounded-context model inside a harness that manages memory, tools, verification and repeated execution. Universality is too coarse a description of such a system: it says nothing about how many model calls a computation needs, how much state must cross the boundary between a small context and a large store, or whether a thousand-step trajectory stays correct. We introduce the Language Model Agent Machine (LAM), a resource-bounded model of a language model together with its harness, in which active context, persistent memory, the memory-access interface, tools and verification are explicit resources, and in which the harness may route and store semantic blocks but never manufacture them. Holding the model fixed, we prove four classes of results, each over a stated comparison class. Communication: for base evaluations of a DAG (one vertex per value-producing call, recomputation allowed, provenance-identified blocks), context–memory traffic corresponds instancewise to red–blue pebbling, so classical I/O lower bounds transfer. Access: on pointer chasing, random access beats every always-correct, non-speculative sequential interface, zero-error randomised or not, by a factor Θ(n)\Theta(n)Θ(n) in memory operations (a sequential head allowed to cache CCC passed-over entries needs only O((n2/C)log⁡C)O((n^2/C)\log C)O((n2/C)logC) expected operations on a random table, tightness open). Recomputation: on base evaluations of bit-reversal DAGs, model calls are Θ(n2/(C+S)+n)\Theta(n^2/(C+S)+n)Θ(n2/(C+S)+n) in context CCC and memory SSS: persistence saves a factor Θ(n/C)\Theta(n/C)Θ(n/C) for C=o(n)C=o(n)C=o(n). Reliability: over nnn dependent transitions on a hard family, stage-local sampling without correctness feedback costs Θ(nγ−2log⁡(n/δ))\Theta(n\gamma^{-2}\log(n/\delta))Θ(nγ−2log(n/δ)) model calls; repeated independent checks by an imperfect verifier are characterized exactly per accepted transition; and segment verification with rollback obeys a Young–Daly-type checkpoint law with a closed-form continuous optimum. Controlled simulations, sampling the theorems’ own error model, reproduce the communication and access scalings and match the exact checkpoint-cost curve to within 1.3%1.3\%1.3%. With a frontier model as the oracle, dependency-only prompting used 7.1×7.1\times7.1× (fixed-width synthetic chain, a template identity) and 11×11\times11× (chained MATH-500, whose depth-1/2 extrapolation runs 14%14\%14% low) fewer logical input tokens than full-history replay, with no prefix-cache hits. The oracle made no error in calibration under the corrected routing, so these runs validate the prompt accounting, not the reliability theory, which is checked only in simulation. The Language Model Agent Machine

Language models are increasingly deployed as components of persistent agentic systems: a harness calls the model repeatedly, keeps state in external memory, invokes tools, and verifies or revises intermediate results over many rounds. Theory has kept pace with the power of such systems, but universality does not distinguish ten model calls from ten million, quantify the state that must cross between a large store and a small context window, or say whether a thousand-step computation stays correct when transitions are imperfect. Universality is in fact cheap in our model, costing O(1)O(1)O(1) model calls and block movements per simulated Turing-machine step at a constant number of context blocks (Proposition 8, appendix). This paper therefore asks a different question: holding the semantic oracle fixed, what does the harness around it spend?

Machine model. The LAM models harness-level execution, the prompt construction, state, memory, tools and verification around a model, not the model’s internal computation. Fix an input size nnn and a finite alphabet Σ\SigmaΣ; a semantic block is a fixed-width unit of task-relevant information, an element of Bn=Σb(n)\mathcal{B}_n=\Sigma^{b(n)}Bn​=Σb(n). A LAM is a tuple

Λ=(L, ctrl, X, M, Otool, Over),\Lambda=(L,\ \mathrm{ctrl},\ X,\ M,\ O_{\mathrm{tool}},\ O_{\mathrm{ver}}),Λ=(L, ctrl, X, M, Otool​, Over​),

where LLL is the model interface, ctrl\mathrm{ctrl}ctrl the harness controller, XXX the active context (at most CCC blocks simultaneously available to the next model call), MMM the persistent memory (at most SSS blocks across calls, outside XXX; a stored block must be retrieved into XXX before it can participate in a call), and OtoolO_{\mathrm{tool}}Otool​ and OverO_{\mathrm{ver}}Over​ the tool and verifier interfaces. A call to LLL consumes blocks in XXX and inserts its output as a new block of XXX, so a call takes at most C−1C-1C−1 argument blocks. A tool call performs an explicitly charged external operation and returns a semantic block; a verifier call returns a tag only (accept/reject) and inserts no block. No interface sees the input, MMM, or a block not passed to it. The controller is a finite control with tag and address registers that sees block contents only through returned tags and decoded addresses.

Value provenance. To separate harness orchestration from semantic computation, every semantic block must originate from the input, a fixed constant, or the output of a model, tool, or verifier call. The controller may route, copy, store, retrieve, and schedule existing blocks, but it cannot generate new task-relevant semantic content on its own. This restriction is load-bearing: without it the lower bounds collapse, so production parsing, ranking, arithmetic or code execution must be charged as explicit computation or lies outside the lower-bound model.

Two classical theories anticipate two of these resources: the red–blue pebble game of Hong and Kung lower-bounds the traffic between a small fast memory and a large slow one, and reliable computation from unreliable components anticipates an agent whose transitions are expensive and imperfect. An agent exhibits both at once, and the LAM recovers and sharpens both classical theories: Theorem 1 transfers every Hong–Kung I/O lower bound instancewise to context–memory traffic, and Theorem 6 recovers the Young–Daly checkpoint law with its exact cost, a closed-form optimum and the class of rollback policies in which it holds.

Every result is stated with the task family and comparison class in which it holds, with explicit constants wherever a separation is quantitative, and this page keeps those scopes attached. The four families answer four design questions, each holding the semantic oracle fixed. Communication: replay or persist?

Theorem 1 (red–blue pebbling correspondence). A base evaluation of an LLL-realisable computation DAG GGG is a deterministic run that evaluates GGG and nothing else: every source block is held in MMM from the start, the context is initially empty, every value-producing call is an LLL-call realising one vertex, blocks are identified by provenance (equal contents make no block a substitute for another), and the run ends with a block for each designated sink resident in XXX or held in MMM. Then every base evaluation with capacities (C,S)(C,S)(C,S) induces a legal red–blue pebbling with at most CCC red and SSS blue pebbles and at most QblkQ_{\mathrm{blk}}Qblk​ load and store moves, and every such pebbling induces a base evaluation on a random-access LAM with the same capacities, one machine per pebbling. Hence

min⁡Qblk  =  IOC,S(G)\min Q_{\mathrm{blk}} \;=\; \mathrm{IO}_{C,S}(G)minQblk​=IOC,S​(G)

over base evaluations, and the minimum is attained by a random-access machine. The correspondence is instancewise, for each fixed GGG, so every red–blue lower bound is a lower bound on QblkQ_{\mathrm{blk}}Qblk​.

Scope. The correspondence holds for a fixed DAG evaluated vertex by vertex, compared with the pebble game at the same capacities, with no distributional assumption over tasks; it needs value provenance and no auxiliary value-producing calls, and it allows recomputation. The converse direction compiles one fixed graph and schedule into a controller, one machine per pebbling; value provenance is what makes the lower-bound direction hold, and the base-evaluation hypothesis excludes constants and streamed outputs.

Design rules, each with the class it holds in

  • Send a step its dependencies, not the history. Holds for chains where each step reads O(1)O(1)O(1) earlier blocks (Proposition 10, appendix), as a saving in logical input tokens. Where the whole task fits in one call, one-call execution is cheaper still.

  • Buy feedback before extra samples only when the check is cheap enough. Real model as the semantic oracle

In the remaining experiments the semantic oracle is a frontier reasoning model, 30 chains per cell. Traffic predictions are plug-in predictions extrapolated from separate calibration data or from the smallest tested instance, with nothing fitted to the larger measurements; the final runs use a routing correction made after inspecting test outputs, disclosed in the paper. Conclusion

Fixing the semantic oracle and charging harness resources makes agent designs comparable by cost at a stated reliability rather than by universality alone. With a frontier model as oracle on vertex-wise chain evaluation, dependency-only prompting used 7.1×7.1\times7.1× and 11×11\times11× fewer logical input tokens than full-history replay; the oracle made no calibration error under the corrected routing, and the reliability laws are matched by controlled simulation, the exact checkpoint-cost curve to within 1.3%1.3\%1.3%.
